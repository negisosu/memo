# データ保護・セキュリティの AWS サービス

## 概要

データ保護・セキュリティでは、暗号化、秘密情報管理、証明書管理、脅威検知、脆弱性管理、機密データ検出を組み合わせます。

| 目的 | 主なサービス |
|---|---|
| 暗号鍵を管理する | AWS KMS |
| 専用 HSM で鍵を管理する | AWS CloudHSM |
| パスワードや API キーを管理する | AWS Secrets Manager |
| TLS 証明書を管理する | AWS Certificate Manager |
| 脅威を検知する | Amazon GuardDuty |
| セキュリティ検出結果を集約する | AWS Security Hub |
| 脆弱性をスキャンする | Amazon Inspector |
| S3 の機密データを検出する | Amazon Macie |

## AWS KMS

AWS KMS は、暗号鍵を作成・管理し、AWS サービスやアプリケーションで暗号化に利用するサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| マネージド鍵管理 | 暗号鍵の作成、ローテーション、アクセス制御を管理できる。 |
| AWS サービス連携 | S3、EBS、RDS、Lambda、CloudTrail などと統合されている。 |
| IAM 連携 | キーポリシーや IAM ポリシーで利用権限を制御する。 |
| 監査可能 | CloudTrail で鍵利用の履歴を確認できる。 |

### 利用例

| シーン | 内容 |
|---|---|
| S3 暗号化 | バケット内オブジェクトを KMS キーで暗号化する。 |
| EBS 暗号化 | EC2 のディスクを暗号化する。 |
| RDS 暗号化 | データベース保存データを暗号化する。 |
| アプリ暗号化 | アプリケーションで機密値を暗号化・復号する。 |

### 向いている利用シーン

- AWS サービスの保管データを暗号化したい
- 鍵の利用権限を細かく制御したい
- 暗号鍵の利用履歴を監査したい
- 自前で鍵管理基盤を持ちたくない

### 注意点

KMS キーの削除は復旧不能な影響を持つ場合があります。削除前に、その鍵で暗号化されたデータが不要か慎重に確認します。

## AWS CloudHSM

AWS CloudHSM は、専用のハードウェアセキュリティモジュールを使って暗号鍵を管理するサービスです。より厳格なコンプライアンス要件や、自社管理の鍵運用が必要な場合に使います。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 専用 HSM | ユーザー専用の HSM クラスターを利用する。 |
| 鍵の自主管理 | 鍵の所有と管理をより強くユーザー側で行える。 |
| 標準 API 対応 | PKCS#11、JCE、OpenSSL などと連携できる。 |
| 高い要件向け | 金融、公共、規制対応などで利用される。 |

### 利用例

| シーン | 内容 |
|---|---|
| 厳格な鍵管理 | 組織が鍵の完全な管理を求めるシステムで使う。 |
| 電子署名 | HSM 内の秘密鍵で署名処理を行う。 |
| 既存暗号処理移行 | HSM 前提の既存アプリを AWS に移行する。 |

### 向いている利用シーン

- 専用 HSM が要件になっている
- KMS よりも自主管理の度合いを高めたい
- 規制や監査で HSM 利用が求められる

### 注意点

CloudHSM は KMS より運用負荷が高くなります。多くの一般的な暗号化要件では、まず KMS を検討します。

## AWS Secrets Manager

AWS Secrets Manager は、データベースパスワード、API キー、OAuth トークンなどのシークレットを安全に保存・取得・ローテーションするサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 秘密情報管理 | パスワードや API キーをコードや環境変数に直書きしない。 |
| 自動ローテーション | 対応する DB などでシークレットを自動更新できる。 |
| KMS 暗号化 | 保存されるシークレットは KMS で暗号化される。 |
| IAM 制御 | 誰が取得できるかを IAM で制御できる。 |

### 利用例

| シーン | 内容 |
|---|---|
| DB パスワード管理 | RDS の接続パスワードを安全に保管する。 |
| API キー管理 | 外部 SaaS の API キーをアプリから取得する。 |
| Lambda 連携 | Lambda が実行時にシークレットを取得する。 |
| ローテーション | DB 認証情報を定期的に変更する。 |

### 向いている利用シーン

- パスワードをコードに埋め込みたくない
- シークレットのローテーションを自動化したい
- シークレットへのアクセスを監査したい
- アプリケーションごとに取得権限を分けたい

### 注意点

頻繁に取得する場合は料金やレイテンシを考慮します。アプリ側で適切にキャッシュする設計が必要な場合があります。

## AWS Certificate Manager

AWS Certificate Manager は、SSL/TLS 証明書を発行、管理、更新するサービスです。CloudFront、ALB、API Gateway などで HTTPS を提供する時に使います。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 証明書発行 | パブリック証明書を発行できる。 |
| 自動更新 | 条件を満たせば証明書更新を自動化できる。 |
| AWS サービス連携 | CloudFront、ALB、API Gateway などに関連付けられる。 |
| インポート対応 | 外部で発行した証明書もインポートできる。 |

### 利用例

| シーン | 内容 |
|---|---|
| HTTPS 化 | ALB に証明書を付けて Web アプリを HTTPS 化する。 |
| CDN 配信 | CloudFront に証明書を設定する。 |
| API 公開 | API Gateway のカスタムドメインに証明書を使う。 |

### 向いている利用シーン

- AWS 上の Web サービスを HTTPS 化したい
- 証明書更新の運用負荷を減らしたい
- CloudFront や ALB と証明書を連携したい

### 注意点

CloudFront で使う証明書は、通常 us-east-1 リージョンで発行・管理する必要があります。

## Amazon GuardDuty

Amazon GuardDuty は、CloudTrail、VPC Flow Logs、DNS ログなどを分析して、不審な挙動や脅威を検出するサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 脅威検知 | 不審な API 操作、通信、マルウェア疑いなどを検出する。 |
| マネージド検出 | ユーザーが検出ロジックを細かく作らなくても利用できる。 |
| 複数アカウント対応 | 組織全体の検出結果を集約できる。 |
| EventBridge 連携 | 検出結果を自動対応フローに渡せる。 |

### 利用例

| シーン | 内容 |
|---|---|
| 侵害検知 | EC2 が不審な外部 IP と通信していることを検出する。 |
| 認証情報漏洩疑い | 普段と異なる国や環境からの API 操作を検出する。 |
| 暗号通貨マイニング疑い | 不審な通信や挙動を検出する。 |

### 向いている利用シーン

- AWS 環境の脅威検知を始めたい
- セキュリティログを自力で全部分析したくない
- 複数アカウントの検出結果を集約したい

### 注意点

GuardDuty は検出サービスであり、防御や遮断を単体で実施するものではありません。検出後は Security Hub、EventBridge、Lambda などで対応フローを設計します。

## AWS Security Hub

AWS Security Hub は、GuardDuty、Inspector、Macie、Config、AWS Firewall Manager などのセキュリティ検出結果を集約し、標準に基づいて評価するサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 検出結果集約 | 複数サービスの findings を一元管理する。 |
| セキュリティ基準 | AWS Foundational Security Best Practices などで評価できる。 |
| 複数アカウント対応 | 組織全体の状態を集約できる。 |
| 自動対応連携 | EventBridge 経由で通知や修復につなげられる。 |

### 利用例

| シーン | 内容 |
|---|---|
| セキュリティダッシュボード | 組織全体の検出結果を一覧する。 |
| コンプライアンス確認 | 標準に対して未対応のリソースを確認する。 |
| インシデント連携 | 重要 findings をチケットや通知に連携する。 |

### 向いている利用シーン

- 複数のセキュリティサービスを使っている
- 検出結果を一元化したい
- 組織全体のセキュリティ状態を見たい

### 注意点

Security Hub は集約と評価のサービスです。個別の脆弱性スキャンや脅威検知そのものは Inspector や GuardDuty などが担当します。

## Amazon Inspector

Amazon Inspector は、EC2、コンテナイメージ、Lambda 関数などの脆弱性を継続的にスキャンするサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 脆弱性管理 | OS パッケージやライブラリの既知脆弱性を検出する。 |
| 継続スキャン | 対象リソースを継続的に評価する。 |
| ECR 連携 | コンテナイメージの脆弱性を検出できる。 |
| Lambda 対応 | Lambda 関数コードや依存関係の脆弱性を検出できる。 |

### 利用例

| シーン | 内容 |
|---|---|
| EC2 脆弱性管理 | 古い OS パッケージや危険度の高い CVE を検出する。 |
| コンテナ検査 | ECR に push したイメージをスキャンする。 |
| Lambda 検査 | 関数の依存ライブラリの脆弱性を確認する。 |

### 向いている利用シーン

- EC2 やコンテナの脆弱性を管理したい
- 継続的に脆弱性を検出したい
- Security Hub と連携して findings を集約したい

### 注意点

Inspector は検出が中心です。修正にはパッチ適用、イメージ再ビルド、ライブラリ更新などの運用が必要です。

## Amazon Macie

Amazon Macie は、S3 に保存されたデータを分析し、個人情報や機密データを検出するサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 機密データ検出 | 個人情報、認証情報、財務情報などを検出する。 |
| S3 評価 | S3 バケットの公開状態や暗号化状態も確認できる。 |
| 自動検出 | 対象バケットを指定して継続的に分析できる。 |
| findings 出力 | 検出結果を Security Hub などに連携できる。 |

### 利用例

| シーン | 内容 |
|---|---|
| 個人情報検出 | S3 に誤って保存された個人情報を見つける。 |
| 公開バケット確認 | 機密データを含むバケットが公開されていないか確認する。 |
| 監査対応 | データ分類や保護状況の確認に使う。 |

### 向いている利用シーン

- S3 に機密データがある可能性がある
- 個人情報の保存場所を把握したい
- データ分類や監査が必要

### 注意点

Macie の主な対象は S3 です。DB 内の機密データ分類などは別の仕組みも検討します。

## 使い分けの目安

| やりたいこと | 主な候補 |
|---|---|
| 保管データを暗号化したい | AWS KMS |
| 専用 HSM が必要 | AWS CloudHSM |
| パスワードを安全に保存したい | AWS Secrets Manager |
| HTTPS 証明書を管理したい | AWS Certificate Manager |
| 不審な挙動を検知したい | Amazon GuardDuty |
| 検出結果を集約したい | AWS Security Hub |
| 脆弱性を見つけたい | Amazon Inspector |
| S3 の機密データを見つけたい | Amazon Macie |
