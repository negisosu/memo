# 災害対策・バックアップの AWS サービス

## 概要

災害対策・バックアップでは、障害や災害が起きた時にデータを失わず、どれだけ早く復旧できるかを設計します。RPO、RTO、コスト、運用負荷に応じて、バックアップ、アーカイブ、レプリケーション、フェイルオーバーを組み合わせます。

| 目的 | 主なサービス |
|---|---|
| バックアップを一元管理する | AWS Backup |
| 長期アーカイブする | Amazon S3 Glacier |
| サーバーを継続レプリケーションする | AWS Elastic Disaster Recovery |
| DNS で障害時切り替えを行う | Route 53 Failover Routing |
| RDS をバックアップ・復元する | RDS Snapshot |
| EC2 のディスクをバックアップする | EBS Snapshot |

## AWS Backup

AWS Backup は、複数の AWS サービスのバックアップを一元管理するサービスです。バックアップポリシー、スケジュール、保持期間、クロスリージョンコピーなどをまとめて管理できます。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 一元管理 | EBS、RDS、DynamoDB、EFS、FSx などをまとめてバックアップできる。 |
| ポリシー管理 | スケジュール、保持期間、ライフサイクルを定義できる。 |
| クロスリージョン | DR 用に別リージョンへコピーできる。 |
| 監査対応 | バックアップ実行状況や保護対象を確認できる。 |
| Organizations 連携 | 複数アカウントにバックアップポリシーを適用できる。 |

### 利用例

| シーン | 内容 |
|---|---|
| 本番環境保護 | RDS、EBS、EFS のバックアップを定期取得する。 |
| 組織標準化 | 全アカウントに共通バックアップポリシーを適用する。 |
| ランサムウェア対策 | バックアップ保管と削除制御を設計する。 |
| DR 準備 | 重要データを別リージョンへコピーする。 |

### 向いている利用シーン

- 複数サービスのバックアップをまとめたい
- バックアップポリシーを標準化したい
- 複数アカウントで統制したい
- 保持期間やリージョンコピーを管理したい

### 注意点

バックアップを取るだけでは災害対策は完了しません。定期的に復元テストを行い、RTO / RPO を満たせるか確認します。

## Amazon S3 Glacier

Amazon S3 Glacier 系のストレージクラスは、長期保存やアーカイブ向けの低コストストレージです。アクセス頻度が低いデータを安く保存するために使います。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 低コスト | 長期保存データを低コストで保管できる。 |
| 複数クラス | Instant Retrieval、Flexible Retrieval、Deep Archive などを選べる。 |
| ライフサイクル連携 | S3 ライフサイクルで自動移行できる。 |
| アーカイブ向け | 監査ログ、法定保存、古いバックアップに向く。 |

### 利用例

| シーン | 内容 |
|---|---|
| 監査ログ保存 | CloudTrail ログを長期間保存する。 |
| 法定保存 | 何年も参照しないが保管義務があるデータを保存する。 |
| 古いバックアップ | ほぼ使わない世代を Deep Archive に移す。 |

### 向いている利用シーン

- 低頻度アクセスのデータを長期保存したい
- コストを抑えてアーカイブしたい
- 復元に時間がかかってもよい

### 注意点

ストレージクラスによって取り出し時間と取り出し料金が異なります。すぐ復旧が必要なデータを Deep Archive に置くと RTO を満たせない可能性があります。

## AWS Elastic Disaster Recovery

AWS Elastic Disaster Recovery は、オンプレミスや他クラウドのサーバーを AWS に継続レプリケーションし、災害時に AWS 上で起動して復旧するサービスです。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 継続レプリケーション | ソースサーバーのディスク変更を AWS に継続同期する。 |
| 低 RPO | 継続同期によりデータ損失を小さくしやすい。 |
| 災害時起動 | 障害時に AWS 上で復旧インスタンスを起動する。 |
| テスト可能 | 本番影響を抑えて復旧テストを実行できる。 |

### 利用例

| シーン | 内容 |
|---|---|
| オンプレ DR | データセンター障害時に AWS 上で業務サーバーを復旧する。 |
| 移行前保護 | クラウド移行前の既存サーバーを DR 対象にする。 |
| 他クラウド DR | 他クラウド上のサーバーを AWS に待機させる。 |

### 向いている利用シーン

- 既存サーバーを大きく改修せず DR 化したい
- バックアップ復元より短い RTO / RPO が必要
- 災害時だけ AWS 上で起動したい

### 注意点

アプリケーションの依存関係、DNS 切り替え、接続先変更、データ整合性は別途設計が必要です。

## Route 53 Failover Routing

Route 53 Failover Routing は、DNS ヘルスチェックと組み合わせて、メイン環境が異常な場合に待機系エンドポイントへ名前解決を切り替えるルーティング方式です。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| DNS フェイルオーバー | 正常なエンドポイントへ DNS 応答を切り替える。 |
| ヘルスチェック | エンドポイントの正常性を監視できる。 |
| DR 連携 | 別リージョンや別環境への切り替えに使える。 |
| シンプル | アプリ入口の切り替え方式として使いやすい。 |

### 利用例

| シーン | 内容 |
|---|---|
| リージョン DR | 東京リージョン障害時に大阪や海外リージョンへ切り替える。 |
| 静的サイト DR | メインサイト障害時に S3 / CloudFront の待機ページへ切り替える。 |
| API 切り替え | メイン API 異常時に待機 API へ誘導する。 |

### 向いている利用シーン

- DNS レベルでフェイルオーバーしたい
- 複数リージョン構成を作りたい
- 比較的シンプルな DR 切り替えをしたい

### 注意点

DNS には TTL やキャッシュがあるため、完全な即時切り替えではありません。アプリケーションやクライアント側の接続保持も考慮します。

## RDS Snapshot

RDS Snapshot は、RDS データベースのバックアップを取得し、必要に応じて復元する機能です。自動バックアップと手動スナップショットがあります。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| DB バックアップ | RDS インスタンスの状態を保存できる。 |
| 自動 / 手動 | 自動バックアップと任意タイミングの手動スナップショットがある。 |
| 復元 | スナップショットから新しい DB インスタンスを作成する。 |
| コピー | 別リージョンや別アカウントへコピーできる。 |

### 利用例

| シーン | 内容 |
|---|---|
| 変更前バックアップ | DB 変更やメンテナンス前に手動スナップショットを取る。 |
| 災害対策 | 重要 DB のスナップショットを別リージョンへコピーする。 |
| 検証環境作成 | 本番データのスナップショットから検証 DB を作る。 |

### 向いている利用シーン

- RDS を復元可能にしたい
- DB 変更前に戻せる状態を作りたい
- 別環境へ DB を複製したい

### 注意点

スナップショット復元は新しい DB として作成されます。既存 DB をその場で巻き戻すというより、復元後に接続先切り替えが必要です。

## EBS Snapshot

EBS Snapshot は、EC2 にアタッチされる EBS ボリュームのポイントインタイムバックアップです。スナップショットから新しい EBS ボリュームや AMI を作成できます。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| ボリュームバックアップ | EBS の状態を保存する。 |
| 増分バックアップ | 変更分を中心に保存する。 |
| 復元 | スナップショットから新しい EBS ボリュームを作る。 |
| AMI 作成 | OS ディスクのスナップショットから AMI を作れる。 |

### 利用例

| シーン | 内容 |
|---|---|
| EC2 保護 | 重要な EC2 のディスクを定期バックアップする。 |
| 作業前保護 | OS 更新やアプリ更新前に取得する。 |
| 複製 | 同じ内容のボリュームを別 AZ に作る。 |

### 向いている利用シーン

- EC2 のディスクをバックアップしたい
- 復旧用の AMI を作りたい
- 作業前の戻し先を確保したい

### 注意点

アプリケーションや DB の整合性を保つには、スナップショット取得前に書き込み停止やアプリケーション整合性の考慮が必要な場合があります。

## 使い分けの目安

| やりたいこと | 主な候補 |
|---|---|
| 複数サービスのバックアップを一元管理したい | AWS Backup |
| 長期アーカイブしたい | S3 Glacier |
| オンプレサーバーを AWS で DR したい | Elastic Disaster Recovery |
| DNS で DR 先へ切り替えたい | Route 53 Failover Routing |
| RDS を復元可能にしたい | RDS Snapshot |
| EC2 のディスクをバックアップしたい | EBS Snapshot |
