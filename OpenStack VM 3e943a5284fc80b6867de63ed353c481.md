# OpenStack 環境の構築方法

レポートの指定により、DevStackを使用

[https://docs.openstack.org/devstack/latest/](https://docs.openstack.org/devstack/latest/)

DevStack公式のQuickStartの手順通りに仮想環境でセットアップ

```bash
# ユーザーを作成する。
# -s bash指定、-d ホームディレクトリを指定、-m ホームディレクトリ作成を設定
sudo useradd -s /bin/bash -d /opt/stack -m stack

# ホームディレクトリに実行権限を付与
sudo chmod +x /opt/stack

# ユーザーstackが全てのコマンドをsudo権限かつパスワード不要に指定
echo "stack ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/stack

# ユーザーをstackに切り替え。-i でログイン時の挙動
sudo -u stack -i

# devstackをclone
git clone https://opendev.org/openstack/devstack
cd devstack

# インストールで必要な変数を事前指定
touch local.conf
vi local.conf

# インストールを実行
./stack.sh
```

## 発生した問題・解決

### Pythonのバージョンが不足

UTMで仮想環境を構築する際に、UbuntuServer22.04のISOファイルを使用していたが、UbuntuServer22.04にはPython3.10がデフォルトで入っており、インストール時に3.12以上のバージョンを要求されたため、デフォルトで3.14が入っているUbuntuServer26.04のISOファイルを使用した仮想環境に作り直した。

## B.OpenStack リソースの作成

#### 目標

openstack内にVMを一台建てて、MacbookのターミナルからSSHできる

### 初期設定

何度かプロトタイプを実行した際に、openstack環境を構築したUbuntuの`/etc/nova/nova-cpu.conf`の設定を書き換えると、VM作成などが安定したため、変更する。

```bash
[libvirt]
virt_type = qemu
cpu_mode = custom
cpu_models = cortex-a57
```

### 手順

改めて各種リソースを確認する

```bash
openstack image show cirros-0.6.3-aarch64-disk
openstack network list
openstack subnet list
openstack router show router1
```

キーペアを作成する

```bash
openstack keypair create \
--public-key ~/.ssh/id_ed25519.pub \
ed25519-key
```

セキュリティグループを作成し、SSH(tcpの22番ポート)とping(icmp)を許可する

```bash
# セキュリティグループ作成
openstack security group rule create \
--description "クラウド第1回課題のSSHとping許可用のセキュリティグループ" \
cloud-sg

# SSHを許可
openstack security group rule create \
--ingress \
--ethertype IPv4 \
--protocol tcp \
--dst-port 22 \
--remote-ip 0.0.0.0/0 \
cloud-sg

# pingを許可
openstack security group rule create \
--ingress \
--ethertype IPv4 \
--protocol icmp \
--remote-ip 0.0.0.0/0 \
cloud-sg
```

既存リソースと作成したキーペア、セキュリティグループを使用して、仮想VMを作成する。

```bash
openstack server create \
--image cirros-0.6.3-aarch64-disk \
--flavor ds2G \
--network private \
--security-group cloud-sg \
--key-name ed25519-key \
--wait \
cloud-cirros-vm \
```

`cloud-cirros-vm`のログで起動しているか確認する

```bash
openstack console log show cloud-cirros-vm
```

起動が確認できたら、仮想VMにFloatingIPを割り当てる。

```bash
# floatingIPの作成と、環境変数への登録
CIRROS_FLOATING_IP=$(openstack floating ip create -f value -c floating_ip_address public)

# IPを確認
echo "$CIRROS_FLOATING_IP"

# 仮想VMにIPを割り当て
openstack server add floating ip cloud-cirros-vm "$CIRROS_FLOATING_IP"

# わり当たっていることを確認
openstack server show cloud-cirros-vm -c addresses
```

SSHジャンプにより、MacOSのターミナルから、仮想VMにSSHできることを確認する（cirrosOSのデフォルトユーザーはcirros）

```bash
# 仮想VMに接続
ssh -J negisosu@192.168.64.26 \
-i ~/.ssh/id_ed25519 \
cirros@"$CIRROS_FLOATING_IP"

# CirrosOSであることを確認
cat /etc/os-release
```

## D. リソースの削除

削除順序は、リソースの関連付けを外していき、参照されなくなった順番に削除していきます。

### 手順

フローティングIPの関連付けから外していいきます。フローティングIPは

**フローティングIP(172.24.4.144)→VMのポート→10.0.0.41**

のように関連付けしているため、VMを削除しても存在しない関連が残ってしまうため、先に関連付けを外します。

```bash
openstack server remove floating ip \
cloud-cirros-vm \
172.24.4.144
```

これによりフローティングIPは何の関連もなくなったため、削除します。

```bash
openstack floating ip delete 172.24.4.144
```

キーペアや、セキュリティグループは仮想VMから関連しているため、まずは仮想VMを削除します。

```bash
openstack server delete --wait cloud-cirros-vm
```

仮想VMの削除が完了したことにより、キーペアとセキュリティグループは参照されていないため、削除します。

```bash
# キーペア削除
openstack keypair delete ed25519-key

# セキュリティグループ削除
openstack security group delete cloud-sg
```

最後に自身が作成したリソースが残っていないか確認します。

```bash
openstack floating ip list
openstack server list
openstack keypair list
openstack security group list
```
