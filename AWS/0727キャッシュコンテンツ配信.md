# キャッシュ・コンテンツ配信の AWS サービス

## 概要

キャッシュ・コンテンツ配信は、ユーザーに近い場所やメモリ上にデータを置き、応答速度を上げたり、オリジンやデータベースの負荷を下げたりするために使います。

| 目的 | 主なサービス |
|---|---|
| 静的・動的コンテンツを高速配信する | Amazon CloudFront |
| アプリケーションのデータをメモリキャッシュする | Amazon ElastiCache |
| グローバル通信経路を最適化する | AWS Global Accelerator |

## Amazon CloudFront

Amazon CloudFront は、AWS の CDN サービスです。世界中のエッジロケーションにコンテンツをキャッシュし、ユーザーに近い場所から配信します。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| エッジ配信 | ユーザーに近い拠点からコンテンツを返す。 |
| オリジン連携 | S3、ALB、EC2、外部 HTTP サーバーなどをオリジンにできる。 |
| HTTPS 対応 | ACM 証明書と連携して HTTPS 配信できる。 |
| WAF 連携 | AWS WAF と組み合わせて Web 攻撃を軽減できる。 |
| キャッシュ制御 | TTL、ヘッダー、Cookie、クエリ文字列でキャッシュ挙動を制御する。 |

### 利用例

| シーン | 内容 |
|---|---|
| 静的サイト配信 | S3 の HTML、CSS、画像、JS を高速配信する。 |
| 画像・動画配信 | 大きなメディアファイルを世界中へ効率よく配信する。 |
| Web API 高速化 | キャッシュ可能な API レスポンスをエッジで返す。 |
| セキュリティ強化 | CloudFront + WAF で公開入口を保護する。 |

### 向いている利用シーン

- 世界中または広範囲のユーザーに配信したい
- S3 や ALB への負荷を下げたい
- 静的コンテンツを高速化したい
- WAF や TLS と組み合わせて公開入口を作りたい

### 注意点

キャッシュされた内容はすぐには変わらない場合があります。頻繁に更新されるコンテンツでは TTL、Cache-Control、Invalidation の設計が重要です。

## Amazon ElastiCache

Amazon ElastiCache は、Redis または Memcached をマネージドで利用できるインメモリキャッシュサービスです。DB へのアクセス負荷を下げたり、セッションやランキングなど高速アクセスが必要なデータを扱ったりします。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| インメモリ | メモリ上で高速にデータを読み書きする。 |
| Redis / Memcached | 用途に応じてエンジンを選べる。 |
| マネージド運用 | パッチ、バックアップ、フェイルオーバーなどを AWS が支援する。 |
| 高速応答 | ミリ秒以下の低レイテンシ用途に向く。 |

### 利用例

| シーン | 内容 |
|---|---|
| DB クエリキャッシュ | 頻繁に読まれる商品情報や設定値をキャッシュする。 |
| セッション管理 | Web アプリのセッション情報を Redis に保存する。 |
| ランキング | ゲームやサービスのランキングを高速に更新する。 |
| レート制限 | API 呼び出し回数を Redis で管理する。 |

### 向いている利用シーン

- DB 負荷を下げたい
- 読み取りが多いデータを高速化したい
- セッションや一時データを共有したい
- リアルタイム性の高いデータ構造を使いたい

### 注意点

キャッシュは永続的な正本データの代わりではありません。データ不整合、TTL、キャッシュ削除、フェイルオーバー時の挙動を設計します。

## AWS Global Accelerator

AWS Global Accelerator は、AWS のグローバルネットワークを使って、ユーザーからアプリケーションまでの通信経路を最適化するサービスです。固定 Anycast IP を提供し、リージョン間のエンドポイントへ効率よくルーティングします。

### 主な特徴

| 特徴 | 説明 |
|---|---|
| 固定 Anycast IP | グローバルに使える固定 IP を提供する。 |
| 経路最適化 | AWS グローバルネットワークを使って通信を最適化する。 |
| ヘルスチェック | 異常なエンドポイントを避けてルーティングできる。 |
| TCP / UDP 対応 | HTTP 以外のアプリケーションにも使いやすい。 |

### 利用例

| シーン | 内容 |
|---|---|
| グローバル API | 複数リージョンの ALB / NLB へ最適にルーティングする。 |
| 固定 IP 要件 | クライアント側で接続先 IP を固定したい。 |
| ゲーム・リアルタイム通信 | UDP や低レイテンシ通信を最適化する。 |
| DR 構成 | 正常なリージョンのエンドポイントへ切り替える。 |

### 向いている利用シーン

- グローバルユーザー向けのアプリを運用している
- 固定 IP が必要
- TCP / UDP 通信の経路を最適化したい
- リージョン障害時の切り替えを速くしたい

### 注意点

CloudFront はコンテンツキャッシュ、Global Accelerator はネットワーク経路最適化が主目的です。Web 静的コンテンツ配信なら CloudFront、TCP/UDP や固定 IP 要件なら Global Accelerator を検討します。

## 使い分けの目安

| やりたいこと | 主な候補 |
|---|---|
| Web コンテンツをキャッシュ配信したい | CloudFront |
| DB の読み取り負荷を下げたい | ElastiCache |
| セッションやランキングを高速処理したい | ElastiCache |
| グローバル通信経路を最適化したい | Global Accelerator |
| 固定 Anycast IP が必要 | Global Accelerator |
